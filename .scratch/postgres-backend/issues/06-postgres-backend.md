## Summary

`store/postgres` — a full second implementation of the capability interfaces on `pgx/v5`, with its
own goose migration set mirroring SQLite's final shape, and real row locking on the money paths.
Nothing runs against it yet in anger; the acceptance bar for this issue is that it compiles, satisfies
the interface, and its SQL is right. Issue 07 proves the behavior.

## Decisions

- **`pgx/v5` through `database/sql`** (`stdlib.OpenDB` / `sql.Open("pgx", dsn)`), not the native pgx
  interface. The whole store is written against `*sql.DB`; keeping that lets both backends share
  method bodies' shape and keeps `DB()` (issue 08) uniform. Direct dependency #6.
- **`accounts` row lock, `FOR UPDATE`, for every check-then-debit.** `Credit` is deliberately
  lock-free: an append-only credit cannot overdraw, and a credit landing after a `Spend`'s snapshot
  only leaves the payer richer than the check believed.
- **`Transfer` locks both accounts in sorted `user_id` order.** Two simultaneous `!give`s in opposite
  directions would otherwise each hold the row the other wants.
- **No materialized balance.** The ledger stays sole truth; at 114 users and ~150 rows each, with
  `ledger_user` indexed, the `SUM` is free. Revisit only on profiling.
- **`BIGINT` unix timestamps, not `timestamptz`** — one code path across both backends, straight
  value copy in the migrate tool.
- **`COLLATE "C"` on every `ORDER BY` over a text name.** A Homebrew cluster initdb'd `en_US.UTF-8`
  orders case- and punctuation-insensitively; SQLite compares bytes. Without this the conformance
  suite's tie-break assertions diverge and it will read like a logic bug rather than a collation
  difference. Applies to `Leaderboard` (`u.display`), `WordleLeaderboard` / `ConnectionsLeaderboard`
  (`display`), and `List` (`commands.name`).

## Work breakdown

1. **`migrations/00001_baseline.sql`** — the six original tables in Postgres spelling. Two things
   differ from SQLite:

   ```sql
   -- BY DEFAULT (not ALWAYS): the one-shot migrate tool inserts explicit ids so
   -- ledger row ids survive the copy, then resets the sequence past the max.
   CREATE TABLE IF NOT EXISTS ledger (
       id      BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
       user_id TEXT   NOT NULL,
       delta   BIGINT NOT NULL,
       reason  TEXT   NOT NULL,
       ref     TEXT,
       ts      BIGINT NOT NULL);
   CREATE UNIQUE INDEX IF NOT EXISTS ledger_ref ON ledger(ref) WHERE ref IS NOT NULL;
   ```

   `users.last_seen` and `ledger.delta`/`ts` become `BIGINT`. Everything else is a direct transcription.

2. **`migrations/00002_accounts_and_rounds.sql`** — the twin of SQLite's `00002`, with
   `game_rounds.state` as `JSONB` and the carry-over using `value::jsonb ->> 'roomID'`. On the real
   cutover the carry-over finds nothing (the database is empty when migrations run; the copy happens
   after), but keeping the two dialects semantically identical is worth more than deleting a no-op.

3. **`lockAccount`** — the helper every money path opens with:

   ```go
   // lockAccount pins userID's account row for the remainder of tx. Every path that
   // reads a balance in order to change it takes this lock first, so check-then-debit
   // is serialized per user. Credit deliberately does not — see the package comment.
   func lockAccount(ctx context.Context, tx *sql.Tx, userID string, now int64) error {
       for attempt := 0; attempt < 2; attempt++ {
           if _, err := tx.ExecContext(ctx,
               `INSERT INTO accounts (user_id, created_at, updated_at) VALUES ($1, $2, $2)
                ON CONFLICT (user_id) DO NOTHING`, userID, now); err != nil {
               return fmt.Errorf("ensure account %s: %w", userID, err)
           }
           var got string
           err := tx.QueryRowContext(ctx,
               `SELECT user_id FROM accounts WHERE user_id = $1 FOR UPDATE`, userID).Scan(&got)
           if err == nil {
               return nil
           }
           if !errors.Is(err, sql.ErrNoRows) {
               return fmt.Errorf("lock account %s: %w", userID, err)
           }
           // A racing inserter held the key while our DO NOTHING ran and then rolled
           // back, so the row we expected isn't there. Our insert wins the retry.
       }
       return fmt.Errorf("lock account %s: row vanished twice", userID)
   }
   ```

4. **`Spend`** — lock, sum, insert, touch, commit, all in one transaction:

   ```go
   tx, err := s.db.BeginTx(ctx, nil)
   defer tx.Rollback()
   if err := lockAccount(ctx, tx, userID, now); err != nil { … }
   tx.QueryRowContext(ctx, `SELECT COALESCE(SUM(delta), 0) FROM ledger WHERE user_id = $1`, userID).Scan(&bal)
   if bal < amount { return false, nil }
   tx.ExecContext(ctx, `INSERT INTO ledger (user_id, delta, reason, ts) VALUES ($1, $2, $3, $4)`,
       userID, -amount, reason, now)
   tx.ExecContext(ctx, `UPDATE accounts SET updated_at = $2 WHERE user_id = $1`, userID, now)
   tx.Commit()
   ```

   `Grant` is the same shape plus the clamp (`if delta < 0 && -delta > bal { applied = -bal }`).

5. **`Transfer`** — sorted lock acquisition before anything else:

   ```go
   first, second := fromID, toID
   if second < first { first, second = second, first }
   // Sorted, always: A→B and B→A running at once would otherwise each hold the
   // row the other wants.
   ```

6. **`Credit`** — the idempotent branch needs the partial index spelled into the conflict target, or
   Postgres cannot infer it and errors **at runtime**:

   ```sql
   INSERT INTO ledger (user_id, delta, reason, ref, ts) VALUES ($1,$2,$3,$4,$5)
   ON CONFLICT (ref) WHERE ref IS NOT NULL DO NOTHING
   ```

   `RowsAffected() == 0` gives `credited = false`, exactly as `INSERT OR IGNORE` does today.

7. **`Leaderboard`** — issue 01's fix, plus the collation:

   ```sql
   SELECT l.user_id, u.login, u.display, SUM(l.delta) AS bal
   FROM ledger l JOIN users u ON u.user_id = l.user_id
   GROUP BY l.user_id, u.login, u.display
   HAVING SUM(l.delta) > 0
   ORDER BY bal DESC, u.display COLLATE "C" ASC
   LIMIT $1
   ```

8. **The rest** — `settings.go`, `rounds.go`, `wordle.go`, `connections.go`: direct transcriptions
   with `$n` placeholders and `ON CONFLICT (col) DO UPDATE SET x = excluded.x`, which is already the
   spelling used today.

9. **Wire it up** — `openStore`'s `postgres://` arm in `bot/store.go`, and the assertion
   `var _ Store = (*postgres.Store)(nil)`. `go mod tidy`.
